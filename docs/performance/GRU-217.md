# GRU-217: Profiler-Vergleich der Kataloglisten

Stand: 2026-07-22

## Ziel und Versuchsaufbau

GRU-217 entfernt die gleichzeitige Montage der Desktop- und Mobilansicht des
Kontrollkatalogs. Gemessen wurde die ungefilterte Route `/katalog/gspp` mit
999 Kontrollen vor und nach der Änderung.

- Baseline: Commit `abe13b8` (unveränderter Stand nach GRU-186)
- Browser: Chrome/Chromium 150, macOS 26.5.2 (arm64)
- Ansichten: Desktop 1440 × 900 px, Mobil 390 × 844 px
- Laufzeit: Vite-Entwicklungsmodus mit React Profiler; für Vorher und Nachher
  identische Instrumentierung
- Stichprobe: fünf vollständige Reloads je Ansicht; angegeben ist der Median
- DOM: Anzahl aller Elemente nach geladener Katalogansicht
- React: größter `actualDuration`-Wert des Katalogaufbaus je Reload
- Long Tasks: Summe der gepufferten `longtask`-Einträge je Reload

Die Werte dienen dem relativen Vergleich dieses Refactorings. Wegen
Entwicklungsmodus, Browserauslastung und kleiner Stichprobe sind sie keine
allgemeinen Produkt-Benchmarks.

## Ergebnis beim Katalogaufbau

| Ansicht | Kennzahl | Vorher | Nachher | Änderung |
| --- | ---: | ---: | ---: | ---: |
| Desktop | montierte Desktop-/Mobilzeilen | 999 / 999 | 999 / 0 | nur eine Liste |
| Desktop | DOM-Elemente | 34.659 | 21.322 | −38,5 % |
| Desktop | React-Commit | 200,1 ms | 169,8 ms | −15,1 % |
| Desktop | Long-Task-Summe | 456 ms | 412 ms | −9,6 % |
| Mobil | montierte Desktop-/Mobilzeilen | 999 / 999 | 0 / 999 | nur eine Liste |
| Mobil | DOM-Elemente | 34.659 | 15.301 | −55,9 % |
| Mobil | React-Commit | 234,5 ms | 163,3 ms | −30,4 % |
| Mobil | Long-Task-Summe | 385 ms | 168 ms | −56,4 % |

Die initiale Medienabfrage liefert in der clientseitigen SPA synchron den
aktuellen Wert. Der Renderzweig montiert deshalb ab dem ersten Client-Render
nur die passende Liste. Die weiterhin vorhandenen `lg:`-Klassen sind eine
CSS-Sicherheitsgrenze für den serverseitigen Fallback, obwohl die Anwendung
derzeit nicht serverseitig rendert.

## Ergebnis bei Auswahländerungen

Nach einem geladenen Katalog wurde dieselbe sichtbare Auswahl fünfmal
abwechselnd gesetzt und entfernt.

| Ansicht | Kennzahl | Vorher | Nachher | Änderung |
| --- | ---: | ---: | ---: | ---: |
| Desktop | Checkbox-Commit (Median) | 136,5 ms | 39,7 ms | −70,9 % |
| Desktop | Toggles mit Long Task | 5 / 5 | 2 / 5 | −3 Vorkommen |
| Mobil | Auswahl-Commit (Median) | 137,0 ms | 6,4 ms | −95,3 % |
| Mobil | Toggles mit Long Task | 5 / 5 | 1 / 5 | −4 Vorkommen |

Die memoisierten Zeilen erhalten nur skalare Auswahlzustände und stabile
Callbacks. Ein Render-Spy-Test weist zusätzlich nach, dass eine unveränderte
Nachbarzeile weder erneut rendert noch ihre Hierarchietiefe neu berechnet.
Beim Öffnen und Schließen einer Tabellenzeile in `BER.3` (33 Kontrollen) lag
der Commit-Median nach dem Refactoring bei 20,0 ms gegenüber einer
`baseDuration` von 32,3 ms; keiner der fünf Wechsel erzeugte einen Long Task.

## Mobile Layout- und Paint-Arbeit

Mobile Referenzzeilen verwenden `content-visibility: auto` und eine anhand der
sichtbaren Zeilen gemessene intrinsische Blockgröße von 5,5 rem (88 px). Der
Browser bestätigte für 999 Zeilen die berechneten Werte
`content-visibility: auto` und `contain-intrinsic-block-size: auto 88px`.
Damit kann er Layout und Paint für weit außerhalb des Viewports liegende
Zeilen überspringen, ohne sie aus DOM, Suche, Fokusreihenfolge oder
Accessibility Tree zu entfernen.

Eine Virtualisierung wurde bewusst nicht Teil von GRU-217: Die Doppelmontage
und Auswahl-Updates waren die gemessenen Hauptursachen, während Windowing die
Grid-, Roving-Tabindex- und Screenreader-Semantik deutlich komplexer machen
würde. Die verbleibenden initialen Long Tasks werden getrennt bewertet.
Das Backlog-Issue [GRU-262](https://linear.app/grundschutz-plus-plus/issue/GRU-262/perfcatalog-verbleibende-initial-long-tasks-produktionsnah-profilieren)
hält dafür Produktionsprofiling und die Bedingungen für eine mögliche spätere
Virtualisierung fest.

## Funktions- und Accessibility-Prüfung

- Breakpoint-Wechsel bewahren Route, Gruppenscope und Checkbox-Auswahl.
- Desktop und Mobil enthalten zu jedem Zeitpunkt genau eine vollständige
  Kontrollliste.
- Das Desktop-Grid besitzt auch nach einer Ergebnisverkürzung genau eine Zeile
  mit `tabIndex=0`.
- Arrow Up/Down, Home/End, Enter und Leertaste behalten ihre bestehende
  Roving-Tabindex-, Öffnen- und Auswahlfunktion.
- `role="grid"`, `role="row"`, `aria-selected` und mobiles `aria-pressed`
  bleiben erhalten.

Die DOM-/Tastaturprüfung erfolgte im Desktop- und mobilen Browser-Viewport.
Ein manueller Test mit physischen iOS-/Android-Geräten sowie VoiceOver oder
TalkBack war in dieser Umgebung nicht verfügbar.
